# Progress: the 1.33.0 guardrails release

Tracking file for the work on branch `chore/guardrails-1.33.0`. The plan is
[2026-10-07-guardrails-review.md](2026-10-07-guardrails-review.md). The maintainer's order is:

1. Guards first: the starting set of restrictions and checks (Phase G).
2. The architecture changes that give each guard one right answer (Phase A).
3. Each bug: a Sonnet subagent fixes it, test first. The same task then goes through the `correct`
   skill (`.claude/skills/correct/SKILL.md`) to strengthen the guard that should have caught it
   (Phase B).
4. One release: no version in intermediate commits. At the end: one bump to 1.33.0, one
   `CHANGELOG.md` section that absorbs the 1.32.4 doc entry, a reply section in the review, and a
   question to the maintainer before any push or tag (Phase R).

## How to resume (read this first after a break or a new session)

1. `cd /Users/nuwan/projects/pet-projects/apiary && git checkout chore/guardrails-1.33.0`.
2. Read the tables below. `done` rows are merged into the branch, so do not redo them.
   - A `running` row had an agent in a worktree when the session stopped. Check
     `git worktree list` and the row's report path under `.agent-reports/guardrails/`.
   - If the report says DONE, merge the worktree branch. Otherwise start a fresh agent in the same
     worktree and give it the remaining items.
3. Start the next `todo` row whose dependencies are `done`.
4. Rules for every row:
   - No AI attribution in commits, and never push, tag or release.
   - Subagents do not touch `package.json` `version` or `CHANGELOG.md`.
   - Never run a bare `git stash`.
   - Create worktrees from this branch with
     `git worktree add .claude/worktrees/<wp> -b wp/<wp> chore/guardrails-1.33.0`, then
     `ln -s ../../../node_modules .claude/worktrees/<wp>/node_modules`.
   - Agent instructions: `.agent-reports/guardrails/INSTRUCTIONS.md`.
   - E2E safety: kill leftover Electron processes, and never launch a packaged app without a
     passing `codesign --verify`.
5. Subagents: `general-purpose` with `model: sonnet`. The repo's `sonnet-low` agent definition is
   not registered when the session starts outside the repo.
